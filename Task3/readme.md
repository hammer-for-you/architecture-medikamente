# Классификация данных

1. Персональные: персональные данные клиентов.

2. Медицинские: истории болезней, результаты анализов.

3. Финансовые: договоры с клиентами, данные оплаты услуг, прочие бухгалтерские документы.

4. Внутренние: корпоративная почта, внутренние акты и распоряжения.

5. Публичные: расписание работы специалистов, прайс-листы.



В первую очередь в защите нуждаются первые три категории данных, как наиболее чувствительные. Внутренние данные компании тоже желательно защитить для сохранения  коммерческой тайны и избежания репутационных потерь. Публичные данные, очевидно, в защите не нуждаются.



# Инструменты защиты

* Защита данных в покое
  
  - Шифрование данных в БД - pgcrypto для PostgreSQL
  
  - Шифрование файлов в файловых хранилищах - MinIO Server-Side Encryption
  
  - KMS для управления ключами шифрования - Hashicorp Vault
  
  - Доступ к данным на основе RBAC/ABAC - Keycloak

* Защита данных in transit
  
  - Использование mTLS
  
  - SMTP TLS + DLP для корпоративной почты
  
  - Использование API Gateway для маршрутизации и управления доступом к эндпойнтам
  
  - Использование хэшей для проверки целостности при передаче файлов



# Автоматизированный контроль

1. Логирование и аудит доступа к данным

2. Сбор логов и метрик приложений

3. Внедрение системы алертинга об инцидентах (например, о попытках несанкционированного доступа к данным)

4. Использование DLP для корпоративной почты

5. Настройка политик ротации ключей для KMS
